# 公平待客暨金融友善週報

網站：<https://finsustcf.github.io/tcf/>

永續金融平台：<https://finsustcf.github.io/sus/>

本儲存庫是已串接 Firebase 的 GitHub Pages 前端，使用主管機關、同業、相關機構與媒體的公開資料，不含公司內部文件。既有後端負責蒐集資訊、以 Gemini 分類摘要並存入 Cloud Firestore；目前已具備登入、排程與多使用者共用資料功能，不是靜態示範頁。

## 閱讀與下載

一般同仁不需要登入。

1. 「上週週報」閱讀上一個完整週一至週日的資訊；「本週資訊」閱讀本週一至今天的資訊。
2. 「自訂日期」選擇開始與結束日期後，按「套用日期」。日期皆以台灣時間計算。
3. 輸入關鍵字、選擇主題或來源地區，即時篩選資訊。
4. 未勾選時，Excel／Word／PowerPoint 下載全部篩選結果；勾選後，只下載已勾選的資訊。
5. 更換搜尋條件、主題、來源地區或資料期間，會清除原先勾選，避免匯出已隱藏的資訊。
6. 「全選篩選結果」包含尚未按「載入更多」顯示的資料。
7. 點「閱讀重點」查看摘要與銀行業務關注點；「查看原文」開啟原始公告或新聞。

下載使用已儲存的內容，在瀏覽器內產製 Office 檔案，不會重新呼叫 Gemini，也不需登入。Excel 包含「週報摘要」、「資訊清單」、「內容補充」三張工作表，Word 與 PowerPoint 保留原文超連結。PowerPoint 每次最多匯出 200 則；單次資料讀取上限為 4,000 則，超過時請縮短期間。

本次版本已修正「先勾選，再切換篩選條件，仍匯出被隱藏資訊」的問題。畫面不提供 AI 依據引文或人工審核流程；內容以原文、摘要及銀行業務關注點呈現。

## 兩站共同介面

公平待客與永續金融使用同一套導覽、期間切換、搜尋、勾選、下載、歷史週報與管理版型。

| 項目 | 公平待客 | 永續金融 |
| --- | --- | --- |
| 配色 | 暖米色／棕色 | 白色／深綠色 |
| 主要內容 | 公平待客、金融友善、金融消費者保護 | 永續金融政策、揭露、氣候與自然風險、銀行案例 |
| 資料與後端 | 原有公平待客集合與函式 | `sus` 獨立集合與函式 |

`app.js`、`styles.css`、`firebase-client.js`、`report-utils.js` 在兩個儲存庫內容相同。平台名稱、分類、功能與後端對照集中於各自的 `data.js`；`index.html` 指定配色及標題，`exports.js` 保留各平台的報告名稱與配色。

日後修改共同操作時，請把這四個共同檔同步更新到兩個儲存庫。請保留各自的 `data.js`、`index.html`、`exports.js` 和圖示，避免誤接另一平台。

## 管理操作

右上角「管理者登入」使用 Google 登入；帳號需在共用的 `admins/<Firebase UID>` 文件中具備 `enabled: true`。已登入的管理員會看到「管理設定」。一般登入帳號不會因此取得管理權限。

- **更新設定**：開啟／暫停自動更新、立即更新、重新彙整上週週報；進階區可調整每日分析及每次處理上限。
- **資訊來源**：查看、啟用或停用來源；可補齊預設來源與新增後端允許的公開網站或 RSS。
- **新增資訊**：提供公開網址；原網站讀取受限時，可補貼同一網址的公開文字。
- **編輯／移除**：開啟目前資訊的詳細內容後操作；歷史封存版不直接編輯。

既有公平待客後端沒有永續版的持久待處理佇列，因此不顯示佇列重試按鈕。更新失敗時可查看最近紀錄，於額度或來源恢復後再更新；此介面更新不會新增後端排程或改變 Gemini 模型。

## 更新排程與資料期間

以下為既有後端的排程設計，實際啟用狀態與成功／失敗紀錄請在管理設定及 Firebase 後台確認。

| 台灣時間 | 工作 |
| --- | --- |
| 每日 06:00 | 蒐集並整理公開資訊 |
| 每週一 07:00 | 產製並封存上一週週報 |

預設每日最多分析 20 次，每次更新最多分析 6 則；產製週報觀察亦會使用同一每日分析上限。失敗的 API 嘗試也可能計入平台分析次數。這些數值是平台自己的限制，不是 Gemini 免費額度保證，也不是 Firebase 計費上限。

資訊按來源發布日納入期間；未標示發布日者，按收錄日整理。「來源地區」表示來源的國內外分類，不等同事件發生地。舊資料沒有地區欄位時，只對已知的臺灣來源識別為「國內」；其餘保留「未標示」，不猜測事件地點。

上週、本週與自訂期間讀取最新已整理資訊；「歷史週報」讀取封存當時的內容。後補資訊、編輯或移除不會自動改寫歷史版，管理員可按「重新彙整上週週報」更新上一週封存。已保存的週報觀察若與最新資訊不同步，不會套用到最新清單。

每週一若本週目前為 0 則，表示尚無發布日或收錄日在本週的已完成資訊，不代表平台一定故障。

## 公開資訊來源

既有預設來源為金融監督管理委員會、金管會銀行局及公平待客原則評核平台；可在管理設定新增後端允許清單中的公開來源。來源類型包含主管機關、同業公告、相關機構與新聞媒體。

僅讀取允許來源的公開內容，不繞過登入、付費牆或網站限制。來源成功連線不代表每期一定有相關新資訊；收錄數量也不代表完整市場趨勢或事件發生率。增加國外來源可能需要修改後端允許清單，並非只新增一個前端選項即可完成。

## Firebase 與資料隔離

| 設定 | 本平台 |
| --- | --- |
| Firebase 專案 | `finsustcf-week` |
| 資料庫 | Cloud Firestore `(default)`；不是 Realtime Database |
| Functions 地區 | `asia-east1` |
| 主要集合 | `articles`、`sources`、`settings`、`runs`、`weeklyReports`、`publicStatus` |
| 共用管理權限 | `admins/<UID>` |
| Gemini Secret | `GEMINI_API_KEY` |
| 模型參數 | `GEMINI_MODEL` |

此儲存庫只有前端，不含 `functions/`、資料庫規則及部署設定；後端版本請保留在原 Firebase 部署專案。僅上傳本次介面更新，不需重新部署 Functions、修改資料庫或重設金鑰。

兩站共用 Firestore 規則與索引。日後部署後端時，請使用同時包含兩平台設定的版本，避免以舊規則蓋掉另一平台的權限或索引。

`firebase-config.js` 是網站連接 Firebase 的公開設定，與 Gemini 金鑰不同。Gemini 金鑰、服務帳號私密金鑰、`.env` 或 `.secret` 不應放入 GitHub 或網頁檔案。兩把 Gemini 金鑰若來自同一個 Google Cloud 專案，仍可能共用該專案配額。

## 更新 GitHub Pages

1. 開啟 `finsustcf/tcf` 儲存庫，選擇 **Add file → Upload files**。
2. 將本次 `tcf` 資料夾內的更新檔案上傳到儲存庫根目錄，包含 `index.html` 和 `README.md`；不要把整個 `tcf` 資料夾再包一層上傳。
3. 保留原有 `vendor/`、`firebase-config.js`、`exports.js`、`favicon.svg`。本次更新沒有替換這些檔案。
4. 提交變更，等待 Pages 部署完成，開啟網站重新整理；Mac Chrome 可按 `Command + Shift + R` 強制重新載入。

既有 Pages 設定維持原值即可；若需重新設定，使用 **Settings → Pages → Deploy from a branch → main → /(root)**。此版本不需執行 npm 安裝或編譯。

## 前端檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 網頁入口、平台標題、主題與載入順序 |

| `exports.js` | 既有 Office 檔案產製模組 |

## 更新後檢查

使用未登入的瀏覽器確認：上週、本週、自訂期間、歷史週報、主題篩選、勾選後換條件，以及三種 Office 下載。再以管理帳號確認更新設定、來源與編輯功能。

若資料為 0 則，先檢查期間；若顯示連線錯誤，依錯誤檢查網路、Firestore 規則或索引。若來源讀取或分析未完成，查看管理設定的「最近一次更新」，不要以反覆下載測試 Gemini。
